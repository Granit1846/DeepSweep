# Выдача ключей ботом (Supabase + Telegram)

Покупатель платит на Boosty, оставляет в комментарии e-mail, присылает этот e-mail боту
и получает код активации за пару секунд. Работает без своего сервера: Telegram сам вызывает
Edge Function Supabase на каждое сообщение.

```
Boosty ──оплата──▶ вы добавляете строку в payments
                        │
покупатель ──e-mail──▶ tg-bot ──claim_code()──▶ codes (пул подписанных кодов)
                        └── код в чат
```

Приватный ключ подписи в облако не попадает: коды готовятся заранее на вашей машине,
Supabase хранит только готовые строки.

## Что где лежит

| Путь | Что это |
|---|---|
| `supabase/migrations/20261102120000_licence_codes.sql` | таблицы `codes`, `payments`, функция `claim_code()` |
| `supabase/functions/tg-bot/index.ts` | сам бот |
| `supabase/config.toml` | `verify_jwt = false` для бота |

Скрипты выпуска кодов (`gen-pool.sh`, `add-payment.sh`, `deploy-bot.sh`) вместе с ключом подписи
намеренно не публикуются и лежат только у продавца. Ниже описано, что каждый из них делает,
чтобы порядок действий был понятен и без самих файлов.

## Установка, один раз

Всё, что ниже, умеет делать один скрипт: положите токены в `.secrets/deepsweep.env`
(шаблон — `.secrets/deepsweep.env.example`), запустите `npx supabase login` один раз и выполните

```bash
tools/license/deploy-bot.sh
```

Скрипт привяжет проект, применит миграцию, поставит секреты, задеплоит функцию и установит
вебхук; повторный запуск безопасен. Дальше останется только загрузить партию кодов (`gen-pool.sh`).
Ручные шаги ниже — для случая, когда что-то из этого нужно сделать по отдельности.

1. **CLI и вход**

   ```bash
   npm i -g supabase        # или scoop/brew
   supabase login
   ```

2. **Привязка к проекту** — `project-ref` виден в URL дашборда: `supabase.com/dashboard/project/<ref>`

   ```bash
   supabase link --project-ref <ref>
   supabase db push          # применит миграцию
   ```

3. **Секреты** (значения не попадают в репозиторий)

   ```bash
   supabase secrets set \
     TG_BOT_TOKEN=123456:AA... \
     TG_SECRET=$(openssl rand -hex 24) \
     TG_ADMIN_CHAT=<ваш telegram id>
   ```

   `SUPABASE_URL` и `SUPABASE_SERVICE_ROLE_KEY` Supabase подставляет в функции сам.

4. **Деплой функции**

   ```bash
   supabase functions deploy tg-bot --no-verify-jwt
   ```

5. **Вебхук** — подставьте свой ref и тот же `TG_SECRET`

   ```bash
   curl "https://api.telegram.org/bot<TG_BOT_TOKEN>/setWebhook" \
     -d "url=https://<ref>.supabase.co/functions/v1/tg-bot" \
     -d "secret_token=<TG_SECRET>" \
     -d "drop_pending_updates=true"
   ```

6. **Первая партия кодов**

   ```bash
   tools/license/gen-pool.sh 25          # создаст tools/license/pool-<дата>.sql
   npx supabase db query --remote --yes -f tools/license/pool-<дата>.sql
   ```

   Проверить в боте: `/pool` (команда только для `TG_ADMIN_CHAT`).

7. **Проверка**: добавить тестовую продажу и пройти путь покупателя.

   ```bash
   tools/license/add-payment.sh TEST-1 you@example.com 1 > /tmp/pay.sql
   npx supabase db query --remote --yes -f /tmp/pay.sql
   ```

   В боте: `/start` → e-mail → должен прийти код. После проверки строку можно удалить.

## Каждая продажа

1. В Boosty видите платёж и комментарий с e-mail.
2. Записываете его одним из двух способов:

   ```bash
   tools/license/add-payment.sh BS-100002 buyer@example.com 399 > /tmp/pay.sql
   npx supabase db query --remote --yes -f /tmp/pay.sql
   ```

   или прямо в боте: `/add BS-100002 buyer@example.com 399`.

3. Покупатель шлёт боту свой e-mail и получает код.

Если человек купил дважды, добавьте две строки: бот выдаст по коду на каждый платёж.
Повторный запрос тем же e-mail в том же чате вернёт тот же код, в другом чате — откажет.

## Команды бота

| Команда | Что делает |
|---|---|
| `/start`, `/help`, `/menu` | приветствие и список команд |
| `/buy`, `/price`, `/shop` | карточка товара: описание, цена, кнопка оплаты |
| `/terms` | условия покупки |
| `/support`, `/paysupport` | поддержка; `/paysupport` обязателен для ботов с платежами |
| `/add <заказ> <e-mail> <сумма>` | админская: внести платёж |
| `/pool` | админская: сколько кодов осталось |

Витрина настраивается переменными, без правки кода: `PRICE_RUB` (по умолчанию `399`),
`BUY_URL` (куда ведёт кнопка «Оплатить», сейчас пост на Boosty), `SUPPORT_URL`,
`PRODUCT_IMAGE_URL` (если задан, карточка уходит фотографией с подписью).

## Если проект общий с другим приложением

Здесь проект Supabase общий с Logbook, и у него своя история миграций. `supabase db push`
из этого репозитория на нём падает:

```
Remote migration versions not found in local migrations directory.
```

Это защита от того, чтобы один репозиторий не переписал схему другого. Правила:

- **Никогда не делайте `supabase migration repair`** на этом проекте: он сдвинет историю
  миграций Logbook, и следующее развёртывание Logbook попытается применить свои миграции заново.
- Новые таблицы и функции применяйте точечно: `npx supabase db query --remote --yes -f файл.sql`.
- Если всё-таки нужен `db push`, делайте это во временном каталоге, где рядом со своей миграцией
  лежат пустые файлы с версиями из истории проекта, и указывайте `--remote=<ref> --include-all`.

## Эксплуатация

| Что | Как |
|---|---|
| Сколько кодов осталось | `/pool` в боте; бот сам предупредит при ≤ 5 |
| Догрузить коды | `tools/license/gen-pool.sh 25` → `npx supabase db query --remote --yes -f …` |
| Проверить вебхук | `curl "https://api.telegram.org/bot<TOKEN>/getWebhookInfo"` |
| Логи функции | дашборд → Edge Functions → tg-bot → Logs |
| Выданные коды | таблица `codes`: `used_at`, `used_by`, `order_id` |

## Ограничения бесплатного тарифа

- **Проект усыпается после недели полного простоя.** Пока идут сообщения — не уснёт; на всякий
  случай можно повесить `pg_cron`-пинг раз в сутки (см. документацию Supabase «Scheduling Edge Functions»).
- Бесплатно: 500 МБ базы (хватит на сотни тысяч кодов), 100 функций, 2 активных проекта.
- Edge Function живёт 150 с и тратит до 2 с CPU на запрос — выдача кода укладывается в миллисекунды.
- Исходящие порты 25/587 закрыты: письма на e-mail из функции не отправить, только Telegram
  (или почтовый сервис с HTTP-API).

## Безопасность

- Приватный ключ подписи — только локально (`tools/license/keys/`, в git не попадает).
- В облаке лежат готовые коды: утечка базы = утечка **невыданных** кодов, поэтому партия небольшая.
- Доступ к таблицам закрыт RLS; работает только `service_role`, то есть сама функция.
- Вебхук защищён `secret_token`; без правильного заголовка функция отвечает 403.
- Код нельзя отозвать — это следствие офлайн-проверки. При возврате денег код остаётся у покупателя.

## Если что-то не работает

| Симптом | Причина |
|---|---|
| Бот молчит | вебхук не установлен или неверный `TG_SECRET` → `getWebhookInfo`, затем повторить `setWebhook` |
| 401/403 в логах функции | забыли `--no-verify-jwt` при деплое |
| «Платёж с таким e-mail не найден» | строки нет в `payments`, другой адрес, или в таблицу попал адрес с опечаткой |
| «Коды закончились» | пул пуст → `gen-pool.sh` |
| Ответ «в другом чате» | код уже выдан по этому e-mail другому аккаунту Telegram |
